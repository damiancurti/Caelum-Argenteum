ID: CA-4360I-SAVE-01

Issue: Legacy release; no original issue recorded. Carried forward by #6.
Test: Manual save/load during maze combat and an activated physical hazard.
Prerequisites: Current Windows 11/GZDoom 4.14.2 checkout; separate test saves
from a fresh 0i-or-later MAP02 and MAP08. Use the configured Save/Load controls;
do not overwrite the author's campaign saves.
Steps:
1. In MAP02, collect loot and a key, then save during a live Mandinga fight.
   Note health, inventory, enemy condition and the chest/door state. Reload
   and resume the fight; save and reload again after it ends.
2. In a separate game run map MAP08. Use the rolling-rock release at
   (1152,1344,0), targeting the rock with TID 43602. Save while the released
   rock is moving, reload, and observe it finish. Run
   netevent ca_debug_hazards_report before and after loading.
3. Activate the trapdoor centered at (1408,896,0). Save/load after it opens,
   climb out using the eastern stairs, leave through the lobby connection
   and return. Do not use the gallery reset lever during this check.
Expected: Combat, health, real inventory, keys and collected loot persist
without duplication. The released rock resumes its saved state; using its
spent lever does not release a new rock. The trapdoor remains open and the
pit/stairs remain traversable after load and hub return. Report each subcase;
a partial pass leaves this test pending.

failure without asserting results for unperformed portions of the test.
